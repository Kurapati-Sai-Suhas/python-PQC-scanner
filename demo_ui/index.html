1What PQScan does

Quantum computers will break RSA and elliptic-curve cryptography. The right post-quantum replacement depends on what each call does: signing → ML-DSA; key agreement → redesign around ML-KEM; RSA encryption → no drop-in, redesign as ML-KEM + KDF + AEAD. PQScan reads the code (never runs it), works out each call's role from evidence, and recommends only when the evidence is strong enough. Otherwise it abstains and says why.

Module ADetect
Semgrep rules find candidate RSA / EC / Ed25519 / X25519 calls
→
Module BGather evidence
Python AST: receiver type, arguments, where the key came from, where it is used
→
Module CRole + tier
SIGN, VERIFY, KEY_ESTABLISHMENT, PK_ENCRYPT ... with evidence tier T0–T3
→
Module DPolicy v1.1
role → guidance; abstain if UNKNOWN or tier below threshold (T2)
→
Module EExports
JSON, CycloneDX 1.6 CBOM (validated), SARIF 2.1.0

8What this demo shows, and what it does not

Shows: the implemented analyser working on real and synthetic Python code, its role decisions, evidence tiers, abstentions and validated exports.
Does not show: accuracy. Whether the recommendations are correct, and more often correct than name-based tools, will be measured on 7 sealed, labelled repositories in the next phase. The statistical simulation passes for fixed repositories; the random-repository scenario (S16) needs an adopted solution before that phase.
Known limits: no TLS/SSH protocol-configuration analysis; tracing stays within one module (2 call levels); PyCryptodome's ML-KEM/ML-DSA modules are not recognised; a detected PQ/T combination shows the data are combined, not that the combiner is certified.
