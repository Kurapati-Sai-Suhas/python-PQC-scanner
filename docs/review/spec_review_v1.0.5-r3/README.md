# Third AI specification review (protocol v1.0.5-r3): prepared, not started

**Nothing has been sent to any AI service.** Each package starts only when the owner chooses to run it. These are AI reviews followed by owner decisions. They are **not** independent human validation and must never be reported as such. The external human review required before F1 is separate and still pending.

## Two packages, two separate fresh sessions

| Package | Purpose | Contents | Parts |
|---|---|---|---|
| **A** (`package_A/`) | Fresh review of the **current** specification without coaching | Fixed instructions, then 23 documents: protocol v1.0.5-r3 and v1.0.3, analysis plan v1.0.1-r3, decisions, run specification (MD and JSON), amendment, guide v1.2-r3, taxonomy, data dictionary, scoring policy, recommendation policy (text and YAML), benchmark schema v1.1, meta schema, AI-review prompt, and the normative code `packets.py`, `candidates.py`, `frame_audit.py`, `multicall.py`, `h2.py`, `guard_diagnostics.py`, `h4.py`. **No** earlier finding, decision record or decision-status page | 9 (about 266,000 characters) |

Run **A first**, in one new Temporary Chat. Run **B** afterwards, in a **different** new Temporary Chat, so the A reviewer never sees the history. Neither package contains labels, tool findings, held-out material, pilot or synthetic answers, site identifiers or identity values. That was checked with a script before commit.

## Owner steps (only when you choose to run them)

1. Confirm `python scripts/spec_review_packet.py --check` exits 0 and ends with `AI-review identity: recorded`. Confirm the identity file still describes the session you will use. If the model or app version changed, record a new identity first.
2. Paste the parts in order. After each part except the last, the reply should be only `RECEIVED PART i OF n`. If the reviewer starts early or reports a truncated part, stop and restart in a new Temporary Chat.
3. Save each reply verbatim outside the repository, with the page saved as PDF. Record the time (UTC) and the SHA-256 of the saved reply.
4. Decide every finding in a copy of `docs/review/spec_review_v1.0.5/owner_decisions_TEMPLATE.csv` (accept, reject with a reason, or defer), and sign off in a copy of `sign_off_TEMPLATE.md`. Any change to a threshold, hypothesis, family, sampling rule or label needs its own explicit owner decision.

## Freezing

Once a package has been sent, its packet is the record of what the reviewer saw. If a document in it changes later, first copy the pre-change text byte-for-byte to `docs/specification/archive/v1.0.5-r3/` (same file name). The packet then keeps reproducing (`--check`).
